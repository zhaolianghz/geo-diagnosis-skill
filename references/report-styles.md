# Report Styles

Resolve style after the diagnosis is structured and before rendering. The diagnostic data is immutable across styles.

| Code | Name | Best for | Visual system |
|---|---|---|---|
| A | 董事会咨询风 | 客户交付、高管汇报、战略诊断 | 暖白纸张、炭黑、暗金单一强调色；编辑式留白与细分隔线 |
| B | 科技战略风 | AI、科技、数字化转型 | 冷白、石墨、克制蓝；更现代但不做 SaaS dashboard |
| C | 品牌研究风 | 市场、品牌、消费者洞察 | 暖中性色、低饱和品牌色；更具编辑感 |
| D | 数据分析风 | 内部运营复盘、分析工作底稿 | 紧凑中性色、表格优先、较高信息密度 |

## Recommendation rules

- Recommend A for client delivery, board review, investment committee, or unspecified business reports.
- Recommend B for technology, AI, and transformation audiences.
- Recommend C when brand narrative and consumer insight lead the story.
- Recommend D when the user explicitly prioritizes density, operations, or internal analysis.

If the user says “自动选择”, pick one using these rules and state the choice in one sentence. If the user supplies a brand color, replace the accent only when contrast remains accessible; do not recolor status semantics.

## Shared presentation constraints

- Approximately 16 px body text and strong heading hierarchy.
- One accent color; red/green only for semantic risk or status.
- No large gradients, neon glows, glassmorphism, decorative 3D charts, or repetitive card stacks.
- Use tables for exact values, bars for relative scores, a single score ring, a two-axis opportunity map, and a linear roadmap.
- Preserve generous whitespace and use short management interpretations before detailed evidence.
- Generated HTML must remain self-contained and printable.
